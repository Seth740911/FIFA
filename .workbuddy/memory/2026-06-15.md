## 视频缓存问题修复

### 问题描述
用户报告：完整看完视频后，再次进入事件页时，视频仍然从网络流播放，而不是从本地缓存播放。

### 原因分析
1. **缓存保存时没有等待 Promise**：在 `_cacheVideoSegments` 和 `_downloadWithoutResume` 函数中，调用 `_saveVideoToDB` 时没有等待它完成，导致页面关闭时缓存可能只保存了一部分。
2. **缓存完整性没有检查**：在 `_setupVideo` 函数中，只检查 `cached.segBlobs.length`，但没有检查缓存是否完整（即是否所有分段都已缓存）。
3. **缺少缓存完成的标记**：保存缓存时，没有标记缓存是否完整，导致不完整的缓存也被使用。

### 修复方案
1. **修改 `_saveVideoToDB` 函数**：
   - 添加了 `complete` 字段，用于标记缓存是否完整
   - 在保存时检查缓存的完整性（比较有效分段数和 m3u8 中的分段数）
   - 返回 Promise，确保调用者能够等待保存完成
   - 使用 `tx.oncomplete` 和 `tx.onerror` 来确保保存完成

2. **修改 `_setupVideo` 函数**：
   - 检查缓存的完整性（`cached && cached.segBlobs && cached.segBlobs.length && cached.complete`）
   - 只有完整的缓存才会被使用，不完整的缓存会重新从网络下载

3. **修改 `_cacheVideoSegments` 函数**：
   - 在保存批次时，等待 `_saveVideoToDB` 返回的 Promise 完成后再继续
   - 确保缓存保存完成后再下载下一个批次

4. **修改 `_downloadWithoutResume` 函数**：
   - 在保存批次时，等待 `_saveVideoToDB` 返回的 Promise 完成后再继续
   - 确保缓存保存完成后再下载下一个批次

### 测试步骤
1. 打开浏览器，进入 FIFA 世界杯应用
2. 点击任意比分条，进入事件页
3. 等待视频开始播放（此时应该从网络流播放）
4. 完整观看视频（或观看至少 80% 的视频）
5. 不要立即关闭页面，等待控制台显示 `[VCACHE] 完成！共下载 XX 段` 的日志
6. 关闭事件页，然后再次点击同一个比分条
7. 此时视频应该从本地缓存播放（可以打开浏览器开发者工具的 Network 面板，确认没有网络请求）

### 注意事项
1. 缓存是在后台进行的，即使视频播放完成，缓存可能还需要一些时间才能完成
2. 如果视频很长，分段很多，缓存可能需要较长时间才能完成
3. 可以在浏览器开发者工具的 Console 面板中查看日志，了解缓存进度
4. 如果缓存失败，会自动回退到从网络流播放
